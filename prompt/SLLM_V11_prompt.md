# SLLM 三模型切换实验 · 任务提示词（修订稿）

## 0. 角色与目标

你是本实验的执行者。目标：在同一组 8 卡（TP8）机器上，让 Kimi-K2.6（K）、GLM-5.1-FP8（G）、DeepSeek-V4-Pro（D）按**同一条已冻结的切换负载**串行激活，分别跑三条路径 A / B1 / B2，产出可对齐的**切换时间**与**CPU/GPU 资源代价**，并证明每一步都真实发生。

- 不是写代码任务，是**实验执行 + 证据生产**任务。
- 结论必须由原生证据支撑；没有证据的项目一律记为"未通过"，不得用推断代替。
- 历史结果只读：**不重跑、不覆盖、不重新解释**。

## 1. 切换序列协议

### 1.1 不再使用单一固定序列

固定五步（`K → G → D → G → K → D` 一类）只作为**示例**，不再是唯一负载。正式实验使用**连续、多方向、可变长度**的序列。

### 1.2 合法转移集

三模型共有 **9 种有序转移**：

- **6 种非自切换**：K→G、K→D、G→K、G→D、D→K、D→G —— 计入正式统计。
- **3 种同模型连续激活**：K→K、G→G、D→D —— 单独统计，**不计入非自切换统计**。

支持任意合法顺序，但"任意"必须落成一个**已冻结的文件**，而不是运行时自由发挥（见 1.3）。

### 1.3 生成、冻结与哈希

1. **生成**：用固定种子的随机游走在 9 种转移上抽样，序列长度取 7 / 8 / 10 三档各若干条（7 是覆盖 6 个非自方向的最短长度）。
2. **覆盖约束**：每条正式序列必须让 6 个非自方向**各至少出现 1 次**；整轮 campaign 每个非自方向累计 **≥3 次**；同模型连续激活的比例 **≤ 1/4**，且单独成表。
3. **冻结**：生成 `switch-sequences.json`，内含 `seed`、生成器版本、序列列表。
4. **协议哈希**：对 `{sequences, seed, 三模型 revision, 量化配置, 上下文长度, 输入与金标集合, 采样参数, vLLM commit, LMCache commit, harness 版本}` 规范化后取 SHA-256，记为 `protocol_hash`。
5. **共用**：三条路径**必须**读同一个 `switch-sequences.json`，每轮开始前校验 `protocol_hash` 一致；不一致即中止，不得"就地改成差不多"。

### 1.4 历史证据边界

- 保留 2026-11-09 已完成的**固定五步**与**十二次随机切换**证据。
- 上述历史运行的序列、统计口径与结论**原样保留**；新增运行按新协议独立编号（如 `campaign-v2-01`），**不得与历史数据混算**，也不得用新结果"修正"旧结论。

## 2. 三条路径

三条路径使用**完全相同的模型集合、revision、量化、上下文长度、输入、金标与序列文件**；唯一变量是"换模型"的机制。

### A：SLLM Store 主方案

1. 一个常驻 SLLM Store 管理三模型的 CPU 权重缓存（固定锁页池、固定块大小）。
2. 每次切换：旧 Backend **正常关闭**并记录退出码 → Store 保持常驻 → 新 Backend 通过 **SLLM Loader** 恢复权重。
3. 重点验证：**缓存命中、真实 eviction、空间复用、重新读取字节、正确推理**。
4. 必须能区分"Store 命中"与"普通 SafeTensors 磁盘加载"；两者不得混称。
5. 若在选定 W 下未自然发生驱逐，允许改用受控容量档（如 896 / 960 GiB）或注入第三个模型的竞争来触发，但必须在报告中标注"人为触发"，不得把受控触发当作自然行为。

### B1：SLLM + LMCache MP 基线

1. 保留与 A **完全相同**的共享 SLLM Store，额外增加 **vLLM GPU KV L1** 与 **LMCache MP 的 CPU Host KV 层**（该层在 LMCache 自身术语中叫 *L1*；本报告统一称 **Host KV 层**，避免与 GPU KV L1 混淆）。
2. 每次切换：确认旧模型 KV 操作全部结束 → 旧 Backend 正常退出 → 清空 Host KV 层（`POST /cache/clear {"tier":"l1"}`，等价于 `lmcache kvcache clear`）→ 启动新模型。LMCache 服务与 SLLM Store 均**不重启**。
3. **不要配置 LMCache 的 L2 adapter（fs / S3 等）**：本组"两层"指 GPU KV L1 + Host 层；多配一层会让"占用归零"无法核实。
4. **不做任何 KV 复用**：关闭 vLLM prefix caching，KV 命中必须为 0（若实现上关不掉，逐次记录命中数并在结论中剔除）；不做跨模型 KV 内容复用，也不做 KV 命中性能优化。
5. "GPU KV Block 重用"的含义**仅限**：旧 Backend 退出后其 GPU KV blocks 被释放，新 Backend 能重新分配——不是跨模型 KV 内容复用。
6. 验证：Host 层实际写入（字节/RSS 可观测）、清理后归零、GPU KV 随进程退出释放、以及相对 A 的增量资源成本。

### B2：Sleep Mode 独立基线

1. **不接 SLLM Store**。只用原生 vLLM 的 Sleep / Memory Saver。
2. **Level 1 与 Level 2 分两组实验，不得混为一种机制。**
   - L1：`sleep(level=1)`，权重备份到 CPU RAM，KV 丢弃；`wake_up` 从 CPU 备份恢复权重、重新分配 KV。
   - L2：`sleep(level=2)`，权重与 KV 均丢弃；`wake_up(tags=["weights"]) → reload_weights → wake_up(tags=["kv_cache"])`，重载源固定为**原生 checkpoint**，记录重载字节数与耗时。
3. 按同一序列执行 Running → Sleep → 下一模型 Running；重复模型再次出现时，尝试 Wake 与必要的权重恢复，并记录成功/失败。
4. **不得以销毁重建替代 Sleep/Wake**：Worker 进程 PID 必须跨 Sleep/Wake 保持不变；PID 变了即判失败，不得改口称为"等价实现"。
5. **前置门槛**：Sleep 释放 HBM 不代表释放 Ray GPU 资源声明、CUDA Context、NCCL 占用。先做一次共置 smoke test（A 睡眠后 B 能否在相同 8 卡启动）；不通过则记录"该配置不满足多模型切换要求"，**不得强杀后伪装成功**。

## 3. 每次切换必须记录

| 类别 | 字段 |
|---|---|
| **时间** | `t0` 旧模型停止接流 / 开始 Sleep；`t1` 旧 Backend 退出 / Sleep 完成；`t2` 新模型开始启动 / Host 层清理完成；`t3` 新模型 ready；`t3.5` 首次 token；`t4` 完整且正确的响应 |
| **CPU RAM** | Store 池总量 / 有效 payload / 空闲块与块账本、LMCache Host 层字节、Sleep 权重备份字节、RSS、cgroup `memory.current`、可用内存 |
| **GPU HBM** | 8 卡逐卡 NVML `memory.used` 与活跃计算进程：切换前、退出或 Sleep 后、新模型运行后 |
| **Store 事件** | 真实 hit / miss、victim、驱逐（含块数与字节）、文件读取字节、块分配与回收、切换前后账本快照 |
| **KV 事件（仅 B1）** | STORE 字节与耗时、`/cache/clear` 的请求/响应与耗时、clear 前后 Host 层记账字节 |
| **正确性** | 正式金标（含固定题）通过情况、**8 个 rank 全部**输出、原始响应、异常记录 |
| **生命周期** | 每个 Backend PID、Store CID / PID / `start_ticks`、LMCache PID、**进程是否存活**、退出码、Sleep 状态 |

**口径要求**：

- **切换时间** = `t0 → t4`，所有动作计入。
- **60 秒释放观察**单列为 `T_observation`，报告须同时给出"含观察"与"不含观察"两版，**不得混入切换时间**。
- 同一模型再次出现时，额外记录**激活前权重驻留字节、实际命中路径数、文件重读字节**。
- 三条路径分别统计；**Sleep / Store 恢复 / KV 层操作不得合并成一种机制**。
- 资源峰值只能表述为"采样峰值"；CPU RSS 与 cgroup **不相加**。

## 4. 执行顺序与验收门

按顺序过门，前一门不过不进入下一门：

| 门 | 内容 | 通过条件 |

| G0 环境 | 核实 qjhs003 的 GPU / CPU RAM / 磁盘 / 在跑任务 / 模型 revision；锁定 vLLM 与 LMCache 版本 | 产出 `env-check.json`，版本 commit 明确 |
| G1 基线正确性 | 三模型在统一目标版本下各跑一次金标 | 8 rank 全部正确 |

| G3 路径 B1 | 两层 KV 真实工作 + 清理可核实 | Host 层写入与归零有字节级证据 |

| G5 对比 | 三条路径跑同一 `protocol_hash` 负载 | 时间与资源可并排比较 |

## 5. 完成标准（逐条可勾选，逐条绑定证据）

1. 三模型在**统一目标版本**下正确运行 —— 证据：`qualification.json` + 原始响应。
2. SLLM Store 在连续切换全程常驻 —— 证据：Store CID / PID / `start_ticks` 全程不变。
3. 实际权重命中、驱逐、空间复用、重新加载均有**原生证据** —— 证据：Store 事件日志 + 块账本快照 + 文件读取字节。
4. B1 的 GPU KV L1、Host KV 层与清理流程真实可用 —— 证据：写入字节、clear 响应、clear 前后归零。
5. B2 的 Sleep/Wake、CPU/GPU 资源变化、多模型切换有独立证据 —— 证据：PID 连续记录、NVML 曲线、L1/L2 分组表。
6. 三条路径使用**同一冻结负载** —— 证据：三份运行日志里的 `protocol_hash` 完全一致。
7. 历史成功、失败与原始数据**全部保留**；新增运行按独立协议编号。

**只有实际通过的项目才能标记完成。**未通过的项目如实标记"未通过"并保留失败数据——不许删、不许改写、不许用"等价实现"绕过。

## 6. 禁止事项

1. 把普通 SafeTensors 磁盘加载当作 Store 命中。
2. 只配参数、未真正运行，就声称 L2 / Host 层已启用。
3. 跨模型保留或复用 KV（B1 含同模型轮内命中）。
4. 用强杀、重建或进程重启冒充 Sleep/Wake，或冒充"Store 常驻"。
5. 把 `T_observation` 混入切换时间，或把不同路径的统计口径"拉平"后再比较。
6. 覆盖、重算或重新解释 2026-11-09 及三模型报告（commit `d3c10bda`）的历史结果；其"图 5 新增 Kimi 补采"与历史样本的统计边界必须原样保留。
