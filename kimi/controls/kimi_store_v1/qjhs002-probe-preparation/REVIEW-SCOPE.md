The GPU guard verifies the exact container identity and GPU request. Before start it queries XML for framebuffer usage and every listed graphics/compute process, checks process cgroup ownership, then starts the container from the same process to remove the earlier ready/external-start race. After a start timeout or later failure it retains the original exception and attempts exact-container cleanup until the fixed guard deadline plus 25 seconds, covering delayed start. Its 2048 MiB threshold is a sampled stop condition, not a hard GPU allocation limit; this does not bound allocation between samples or driver/runtime stalls.

The archived stdlib regressions were rerun without Torch, CUDA, Docker, Store, or network: test_deadline_gpu_failures.py completed rc0 for over_threshold, foreign_pid (graphics process), query_timeout, and late_start_after_timeout; test_component_cleanup.py completed rc0, one test with ten subcases.
