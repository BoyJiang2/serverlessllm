# Store host controller prepared

benchmarks/v4_run_once.py incorporates the exact qualified native controller archived in v4-native-reference-success/successful-run/controller-executed.py. Its full lineage diff is retained. The selected native engine, CUDA precheck, device order, read-only weights, UID2147 profile, memory/CPU/container bounds, detached guard, worker identity tracking and >=60-second release collector are reused. This controller is execution/evidence support, not a new SLLM or V4 loading mechanism.

The explicit store-conversion mode mounts only the task Store parent writable and overlays only the reviewed v4_convert.py in site-packages, preserving the installed native libraries. It uses a fresh conversion ID/directory, explicit loader plugin and existing phase tracing. The qualified native JIT cache is reused after its small binary manifest is verified; no weights are copied or rehashed. The child verifies the converter overlay hash from the preparation receipt before invoking the guarded Store entry.

Before initial preparation and again before launch, available storage must cover a 1 TiB write budget plus a 128 GiB floor; host available memory must cover the unchanged 1 TiB container limit plus 64 GiB. Store storage must be local XFS. During execution, logical and allocated Store bytes must each stay <=1 TiB, free disk >=128 GiB and host available memory >=64 GiB. The sampled threshold record is persisted before a violation triggers exact-container cleanup. These are sampled stop thresholds, not exclusive reservations, global writer leases or guarantees against between-sample pressure. Partial data is preserved and never automatically resumed.

The 1080-second container and 1200-second overall bounds remain. They include preparation and Store completion hashing; a slower conversion stops rather than extending the deadline. Successful COMPLETE/candidate records do not substitute for independent normal exit and physical release review. Controller failure, selected-GPU/process cleanup and formal experiment outcomes remain separate.

CLI: python3 benchmarks/v4_run_once.py ABSOLUTE_NEW_EVIDENCE_DIR REVIEWED_SOURCE_HEAD store-conversion prints a plan and exits without creating the job/Store/container or importing Torch/vLLM/Ray/native extensions. Adding --execute enters preparation, then waits for GO.json. That file must record the matching purpose/source head, the applicable stage authorization and prior GPU notification. A string in a file is audit provenance, not an authorization grant: the operator must already have the user-approved scope. No GO was issued and no GPU/Store model job was started in this batch.

Nineteen CPU contracts pass, including AST-isolated generated wrappers/commands, storage/host thresholds, GO rejection and preserved native guard/entry behavior. The actual target-host default plan passed without claiming paths or importing inference libraries. Raw log, source hashes and plan are in evidence/v4-store-controller-preparation. No full model run, Store conversion/recovery, daemon/pool/IPC or service lifecycle qualification is claimed. Prior runtime scope excluded Store conversion; current routine continuation has not been used to silently replace that boundary. Formal IDs and gold are unchanged.
