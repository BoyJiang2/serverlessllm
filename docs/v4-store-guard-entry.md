# Bounded Store conversion entry

The existing container guard now accepts the explicit store-conversion purpose, requiring a matching label on a new retained container with no restart. Native-reference remains the default. Full immutable ID, Created/Image binding, absolute deadline within 1200 seconds, inspect-timeout handling and exact-ID kill are preserved. The armed receipt binds purpose. This is orchestration support, not a new model loading mechanism or runtime authorization.

benchmarks/v4_store_conversion.py defaults to a metadata-only plan using the existing converter. Execution requires --execute, --guard and --output, the current container hostname, a current store-conversion guard, the installed sllm_v4_store plugin and target vLLM. It calls the existing full grouped coordinator without relaxing eight-rank receipts, shutdown, payload validation or COMPLETE publication. Output is only a candidate pending independent host release/review; exceptions retain their traceback. No retry, automatic resume, daemon, pool policy or formal statistics are introduced.

These are sleep containers, not Store, IPC, physical GPU release or 60-second observations. Actual default entry against the model config imports no Torch/vLLM/Ray/native extension, constructs no model and claims no Store directory.
